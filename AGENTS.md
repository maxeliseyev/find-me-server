# AGENTS.md — find-me-server

Контракт для людей и агентов в этом репозитории. Детали — в `docs/`;
сюда попадают только инварианты, которые нельзя «улучшить» по ходу задачи.

**Первый файл любой сессии — `docs/status.md`.** Чат предыдущего агента может
отсутствовать. Если `status.md` расходится с git — чини его до кода.

| Зона | Читать сначала |
|---|---|

| Протокол смены, что куда писать | `docs/handoff.md` |
| Продукт: роли, сценарии, модель данных, этапы | `docs/spec-poisk-zhivotnyh.md` |

Не копируй эти документы в чат и не дублируй их в код-комментариях.

## Что это

Бэкенд сервиса поиска потерянных животных. Django 5.2 LTS + GeoDjango,
PostgreSQL 16 + PostGIS, Redis, Celery, aiogram, `uv`.

**Первичная сущность — отметка о наблюдении, а не объявление.** Существующие
сервисы — доски объявлений, и в них некуда деть сообщение «видел похожую собаку
у гаражей вчера в семь». Здесь такое сообщение — полноценная запись, и вокруг
него строится всё остальное: трек, зона поиска, уведомления.

Продукт отвечает владельцу на вопрос «куда идти сегодня», а не показывает ленту.

Что проект не делает: пристройство и приюты, база чипирования, передержка,
федеральный охват на старте. Запуск — один город, один район.

Сейчас: **этап 1 — ядро** (модель данных, карта, объявление, отметка, бот с
подпиской; без чата и трека). Этапы — раздел 11 спеки.

## Команды

Канон — `make` (обёртка над `uv` и `docker compose`).

```bash
make install      # uv sync --all-extras
make up           # postgis + redis
make migrate / mm
make run          # dev-сервер
make worker / beat / bot
make test         # pytest
make lint / fmt   # ruff
```

Системные GDAL/GEOS обязательны (`brew install gdal geos proj`); пути к ним —
в `.env` (`GDAL_LIBRARY_PATH`, `GEOS_LIBRARY_PATH`), если Django их не находит.

Перед тем как считать задачу сделанной: `make lint` и `make test` зелёные,
`makemigrations --check` чистый.

apps/moderation/ жалобы, автоскрытие, лог модератора

bot/             aiogram отдельным процессом на общей БД

Доменная логика — в `services.py` / `selectors.py` / модулях приложения, не во
вьюхах и не в сериализаторах. Вьюха валидирует вход и зовёт функцию.

Бот не дублирует бизнес-логику: он вызывает те же функции приложения, что и API.

## Инварианты

Нарушить любой пункт = регрессия, даже если «так проще».

1. **До отправки отметки — ноль экранов регистрации.** `Sighting.author` и
   `Sighting.report` остаются nullable. Отметка сохраняется даже если человек
   не авторизовался и не выбрал объявление. Это причина, по которой продукт
   существует; «просто добавим обязательную авторизацию» — отмена продукта.
   Канон: `docs/decisions/sighting-is-primary-entity.md`.
2. **Неопознанная отметка живёт сама по себе.** Привязка к объявлению —
   действие пользователя (v1) или подсказка (v2), но не условие сохранения.
3. **Точная точка пропажи не уходит наружу.** В публичную выдачу идёт
   `LostReport.public_geog` (смещение на `PUBLIC_LOCATION_BLUR_M`), точная —
   только по явному решению владельца и только в чате. Смещение
   детерминировано по id объявления: случайное на каждый запрос усредняется
   и восстанавливает подъезд. Канон: `docs/decisions/exact-location-is-never-public.md`.
4. **EXIF режется перед отдачей.** GPS из фото читаем на сервере (это ценные
   данные для автопозиционирования), но наружу не выходит ни один снимок с
   метаданными. Флаг `SightingPhoto.exif_stripped` — не для украшения.
5. **Телефон не публикуется никогда.** Контакт — внутренний чат или телеграм.
   Поля «публичный телефон» в API не появляется ни под каким соусом.
6. **Все координаты — `geography(Point, 4326)` с GiST-индексом.** Расстояния
   считаются в метрах через PostGIS (`ST_DWithin`, `Distance`), не в градусах
   и не питоном по выборке всей таблицы.
7. **`seen_at` и `created_at` — разные факты и не схлопываются.** Человек
   ставит отметку о вчерашнем наблюдении; вес считается по `seen_at`.
   Время везде timestamptz, `USE_TZ = True`.
8. **Вес отметки считается по формуле раздела 6.2 спеки**, хранится в поле
   `weight` и пересчитывается фоновой задачей. Не считать его во вьюхе,
   не сортировать выдачу «по свежести» в обход весов.
9. **Зона поиска — оценка, а не истина.** API отдаёт её как GeoJSON с явным
   признаком расчётности; интерфейс обязан писать это словами. Никаких
   формулировок «животное здесь».
10. **Уведомления защищены от выгорания.** Суточный потолок на пользователя,
    тихие часы (сквозь них проходят только отметки «животное у меня»), дедуп
    в окне. Каждая отправка и каждое подавление — строка в `NotificationLog`.
    Отписавшийся волонтёр не возвращается; это дороже пропущенного уведомления.
    Канон: `docs/decisions/telegram-is-the-notification-transport.md`.
11. **Фан-аут, пересчёт зон и обработка фото — Celery.** В цикле
    request/response их нет: очевидец ставит отметку с телефона в подъезде.
12. **Рейтлимит на анонимные отметки не снимается «для удобства».** Для
    неавторизованного действия это единственная защита.
13. **Модерация обязательна к сохранению работоспособной:** автоскрытие при N
    жалобах до разбора, лог действий модератора, кнопка жалобы у каждой
    пользовательской сущности. UGC-сервис без модерации умирает за месяц —
    это причина выбора Django. Канон: `docs/decisions/django-over-fastapi.md`.
14. **Django-админка — инструмент модератора, а не пользовательский интерфейс.**
    Пользовательские сценарии живут в API и боте.
15. **Не тащить в v1 распознавание морд, эмбеддинги и автоматический матчинг.**
    Дорого, эффектно на демо, бесполезно без данных. Это v2 (раздел 4 спеки).
16. **Миграции применённые не правятся.** Изменение — новой миграцией.
    `makemigrations --check --dry-run` в CI обязан быть чистым.
17. **Секреты только через env.** `.env` не коммитится; новая переменная
    добавляется в `.env.example` в том же изменении.
18. **Город и район пилота не хардкодятся** ни в коде, ни в миграциях: центр
    карты, радиусы и тайлы — настройки.

## Python / Django

- Python 3.13, Django 5.2 LTS. Версию Django не бампать «заодно»: следующий LTS
  — 6.2, переход отдельным PR.
- Зависимости — `uv` (`pyproject.toml` + `uv.lock`). `pip install` в обход
  lock-файла не использовать; lock коммитится.
- Стиль: `ruff` (line-length 100), `ruff format`. Импорты сортирует ruff.
- `verbose_name` у моделей и полей — по-русски: их видит модератор в админке.
- Названия в коде — латиницей, комментарии и docstring — по-русски, как вокруг.
- Комментарий только на неочевидное: почему смещение детерминировано, почему
  тихие часы не действуют на «животное у меня». Не комментировать очевидное.
- Пороги, влияющие на продукт (радиус смещения, потолок уведомлений, период
  полураспада веса), — именованные настройки в `config/settings/base.py`,
  не литералы по коду.
- Никаких `select_related`-заглушек ради «оптимизации» без замера; но выборка
  подписчиков и карты обязана быть одним запросом, а не циклом.

## Тесты

Цель — тест, который может провалиться на известном дефекте, не coverage.

Обязательны для PR, который трогает:

- **гео** — смещение не выходит за радиус, детерминировано по seed, точная
  точка не попадает в публичный сериализатор;
- **отметки** — сохранение анонимной отметки без `author` и без `report`;
- **веса** — затухание по `seen_at`, разница `device_gps` / `manual_pin`;
- **фан-аут** — попадание в радиус, фильтр по виду, тихие часы, суточный
  потолок, дедуп;
- **EXIF** — на выходе метаданных нет;
- **модерацию** — автоскрытие при N жалобах.

Тесты гоняются на живом PostGIS (`make up`), не на sqlite: половина инвариантов
здесь — про PostGIS. Помеченный `xfail` известный дефект лучше, чем строчка в
списке Open.

## Как работаем

Полный флоу: `docs/git-workflow.md`. ADR: `docs/decisions/git-trunk-until-v1.md`.

До первой версии в проде **нет ветки `develop`**. Интеграция — только `main`.
Вся работа, включая автора репо, идёт ветка → PR → squash в `main`.
**Прямой пуш и прямой коммит в `main` запрещены.** Ошиблись веткой — перенести
коммиты в feature-ветку, а не «оставим, там же мелочь».

Ветки от актуального `main`: `feat/…`, `fix/…`, `chore/…`, `docs/…`, `test/…`.
Коммиты — [Conventional Commits](https://www.conventionalcommits.org/):
`feat(sightings): …`, `fix(geo): …`, `docs: …`.

Один PR — один шаг. Не смешивать модель данных и бота «чтобы сразу было видно».

Незаконченная работа живёт на запушенной feature-ветке, имя которой стоит в
`docs/status.md`. Не на `main`, не только в чате, не только в local working tree.

Definition of done:

1. Инварианты выше не нарушены.
2. `make lint` и `make test` зелёные; `makemigrations --check` чистый.
3. Если менялись модели — миграция в том же PR.
4. Если менялось поведение — есть тест, который падал бы до правки.
5. Если добавилась настройка — она в `.env.example`.
6. `docs/status.md` соответствует git (Branch, Now, Next, Resume).
7. Нетривиальное решение — session note с **Why**; ограничивающее будущее — ADR.
8. Менялось поведение или канон — `VERSION` и `CHANGELOG.md` в том же PR.

Не коммить `.env`, `media/`, `staticfiles/`, `.DS_Store`.

## Смена сессии

Шаблоны: `docs/handoff.md`.

**Старт** (пока не сделано — не писать фичу):

1. `git status -sb`, ветка, последние коммиты, открытые PR.
2. `docs/status.md` целиком.
3. Session note, на которую ссылается `status.md`, если ссылается.

**Конец** (и когда «ещё не готово»):

1. Код на feature-ветке; ветку **push**.
2. Переписать `status.md`: Branch, Now, Next, Resume обязательны.
3. Session note, если было Why / тупик / нетривиальный баг.
4. Канон (спека, этот файл, ADR) — в том же изменении, что и поведение.

`status.md` перезаписывать, не дописывать летопись. Летопись = git + `sessions/`.

## Документация

Один дом на факт — таблица в `docs/handoff.md`. Кратко:

- курсор смены → `docs/status.md`;
- почему в этой сессии → `docs/sessions/`;
- повторно всплывёт → `docs/decisions/`;
- что за продукт, роли, модель данных, этапы → `docs/spec-poisk-zhivotnyh.md`;
- нельзя нарушить → этот файл.

Спеку не переписывать сюда. Меняешь продуктовое решение — правь спеку в том же
изменении и оставляй ADR, если решение ограничивает будущую работу.

Черновики агента, дампы чата и «как я думал» в `apps/` не класть.
