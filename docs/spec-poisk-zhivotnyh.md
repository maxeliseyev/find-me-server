Статус: черновик, обсуждается
Автор: Max
Дата: сентябрь 2026

---

## 1. Суть и позиционирование

### Проблема

Когда у человека пропадает животное, работает не интернет, а ноги: люди физически прочёсывают район. Существующие сервисы (Pet911, PoiskZoo, ZooSearch, региональные доски, группы в ВК и Telegram) — это **доски объявлений**. Они устроены так:

- владелец подаёт объявление «пропал»
- нашедший подаёт отдельное объявление «найден»
- сопоставляет их либо человек глазами, либо алгоритм по фото

При этом теряется главное — **информация о наблюдениях**. Человек, который просто видел похожую собаку у гаражей вчера в семь вечера, не будет заводить объявление «найдена собака». Он её не нашёл. Он её видел. Для такого сообщения в существующих сервисах нет формата, и оно уходит в комментарии, в чат дома, или никуда.

### Продукт

Сервис, где первичная сущность — **отметка о наблюдении**, а не объявление. Отметки накапливаются вокруг пропавшего животного, ложатся на карту с временными метками и складываются в **трек перемещения** и актуальную зону поиска.

Владелец получает не ленту, а ответ на вопрос «куда идти сегодня».
Волонтёр получает карту с приоритетными квадратами, а не список объявлений.

### Чем отличается от конкурентов

| | Существующие сервисы | Этот проект |
|---|---|---|
| Первичная сущность | Объявление | Отметка о наблюдении |
| Точка входа | «Подать объявление» | Карта + «Я видел животное» |
| Наблюдение без опознания | Некуда деть | Полноценная сущность |
| Результат для владельца | Список похожих объявлений | Зона поиска на сегодня |
| Уведомления | Email / пуш в приложении | Telegram-бот с гео-подпиской |
| Деньги | Платное продвижение объявлений | См. раздел 12 (открыто) |

### Чего проект НЕ делает

- не занимается пристройством и приютами
- не ведёт базу чипирования (только ссылается на существующие)
- не берёт на себя транспортировку, передержку, ветеринарию
- не строит федеральный охват на старте — запуск в одном городе

## 2. Роли

**Владелец** — потерял животное. Создаёт объявление, видит отметки и зону поиска, общается с очевидцами.

**Очевидец** — видел животное на улице. Ставит отметку. Может не иметь аккаунта на момент первого действия. Самая массовая и самая ценная роль. Весь UX затачивается под неё.

**Нашедший** — животное у него на руках. Частный случай очевидца с флагом «животное при мне».

**Волонтёр** — подписан на район, получает уведомления, ищет системно. Отличается от очевидца наличием гео-подписки и историей подтверждённых отметок.

**Модератор** — разбирает жалобы, скрывает мусор, банит.

## 3. Ключевые сценарии

### 3.1 Очевидец ставит отметку (главный сценарий)

1. Открывает ссылку (из телеграм-канала, от знакомого, с расклеенного QR)
2. Видит карту своего района с активными объявлениями
3. Жмёт «Я видел животное»
4. Либо выбирает объявление, на которое похоже, либо ставит отметку без привязки
5. Указывает точку (по умолчанию — геолокация устройства), время, фото по желанию
6. Отправляет

**Требование: до отправки отметки — ноль экранов регистрации.** Авторизация запрашивается после, чтобы можно было получить ответ владельца. Отметка сохраняется в любом случае.

### 3.2 Владелец создаёт объявление

1. Вид, окрас, размер, пол, приметы, кличка
2. Фото (минимум 1, желательно анфас)
3. Точка и время последнего наблюдения
4. Номер чипа/клейма, если есть
5. Контакт — только через внутренний чат или телеграм, не публичный телефон
6. Автоматически: подписка на все отметки в радиусе

### 3.3 Волонтёр подписывается на район

1. В боте: «Следить за районом»
2. Отправляет геолокацию или выбирает точку на карте, задаёт радиус
3. Получает уведомления о новых объявлениях и об отметках в своей зоне

### 3.4 Владелец видит зону поиска

Карта показывает:
- точку пропажи
- отметки, отсортированные по времени, с визуальным затуханием старых
- расчётную зону вероятного нахождения на текущий момент
- предполагаемый вектор движения, если отметок хватает

## 5. Модель данных

PostgreSQL + PostGIS. Все координаты — `geography(Point, 4326)`, индексы GiST.

```sql
-- Пользователь
users (
  id, telegram_id, username, display_name,
  phone_verified bool, created_at,
  trust_score int,          -- см. раздел 9
  is_banned bool
)

-- Животное (отделено от объявления: одно животное может теряться дважды)
pets (
  id, owner_id,
  species enum('dog','cat','bird','other'),
  breed text, colors text[], size enum, sex enum,
  features text,            -- приметы
  chip_number text, brand_number text,
  photos jsonb
)

-- Объявление о пропаже
lost_reports (
  id, pet_id, author_id,
  last_seen_at timestamptz,
  last_seen_geog geography(Point,4326),
  location_precision enum('exact','blurred'),  -- см. раздел 8
  search_radius_m int,
  status enum('active','found','archived','hidden'),
  reward_text text,
  created_at, updated_at
)

-- Отметка о наблюдении — ЦЕНТРАЛЬНАЯ СУЩНОСТЬ
sightings (
  id,
  report_id nullable,       -- NULL = неопознанное наблюдение
  author_id nullable,       -- NULL = анонимная отметка
  geog geography(Point,4326),
  seen_at timestamptz,
  created_at timestamptz,
  source enum('device_gps','manual_pin'),   -- влияет на вес
  animal_in_custody bool,   -- «животное у меня»
  species enum, colors text[],
  photos jsonb,
  comment text,
  confidence enum('sure','maybe','unsure'),
  weight float,             -- вычисляемый, см. 6.2
  status enum('visible','hidden','spam')
)

-- Гео-подписка
geo_subscriptions (
  id, user_id,
  geog geography(Point,4326),
  radius_m int,
  species_filter enum[],
  active bool,
  quiet_hours int4range
)

-- Модерация
reports_abuse (
  id, target_type, target_id, reporter_id, reason, created_at, resolved_by
)

-- Чат
threads (id, report_id, participant_ids)
messages (id, thread_id, author_id, body, created_at)
```

### Ключевые индексы

```sql
CREATE INDEX ON sightings USING GIST (geog);
CREATE INDEX ON sightings (report_id, seen_at DESC);
CREATE INDEX ON lost_reports USING GIST (last_seen_geog) WHERE status = 'active';
CREATE INDEX ON geo_subscriptions USING GIST (geog) WHERE active;
```

### Почему `report_id` nullable

Это принципиально. Половина полезных сообщений — «видел рыжего кота у пятого дома, не знаю чей». Если требовать привязку к объявлению, эта половина теряется. Неопознанные отметки живут сами по себе и подтягиваются к объявлениям потом — вручную в v1, полуавтоматически в v2.

## 6. Ключевая механика: трек и зона поиска

### 6.1 Что показываем

- Точки наблюдений с прозрачностью, зависящей от давности
- Линия предполагаемого маршрута, если отметок ≥ 3 и они выстраиваются во времени
- Полигон «зона поиска на сегодня» — тепловая карта вероятности

### 6.2 Вес отметки

```
weight = w_recency × w_source × w_trust × w_confidence
```

- `w_recency` — экспоненциальное затухание, период полураспада порядка 12 часов для кошек, больше для собак (кошки прячутся рядом, собаки уходят далеко)
- `w_source` — `device_gps` весит заметно больше, чем `manual_pin`
- `w_trust` — репутация автора: подтверждённые отметки в прошлом повышают, жалобы понижают
- `w_confidence` — что выбрал сам человек

### 6.3 Расчёт зоны

Ядерная оценка плотности по взвешенным точкам. Радиус ядра растёт со временем от последнего наблюдения — неопределённость увеличивается.

Считается фоновой задачей, кэшируется в Redis, отдаётся клиенту как GeoJSON. Пересчёт при новой отметке и по расписанию.

**Важно:** зона — это подсказка, а не истина. В интерфейсе должно быть честно написано, что это оценка по имеющимся данным.

## 7. Архитектура и стек

### Бэкенд

**Django + GeoDjango.** Обоснование: UGC-сервис без модерации умирает за месяц, а Django-админка даёт модераторский интерфейс почти бесплатно. Нагрузка тут скромная, преимущества FastAPI по производительности нерелевантны.

- PostgreSQL 16 + PostGIS
- Redis — кэш, очередь, дедупликация уведомлений
- Celery или ARQ — фоновые задачи: фан-аут уведомлений, пересчёт зон, обработка фото
- S3-совместимое хранилище для фото
- Docker Compose на старте, дальше по обстоятельствам

Go можно вынести отдельным сервисом позже, если упрётся тайлы или матчинг. На старте не нужен.

### Фронтенд

- PWA: карта + подача объявления + отметка
- MapLibre GL JS. Тайлы — либо своя сборка, либо Яндекс/2ГИС, если приоритет скорость запуска в РФ
- Кластеризация точек на сервере, не на клиенте
- Офлайн-кеш карты района — полезно, когда человек ходит по дворам с плохой связью

### Telegram-бот

aiogram. Отдельный процесс, общая БД.

## 8. Уведомления

### Почему бот, а не веб-пуши

На iOS Push API доступен только веб-приложениям, добавленным на домашний экран через Safari. Обычная вкладка пушей не получит. В ЕС Apple вырезала standalone-PWA под DMA, там веб-пуши не работают вовсе.

Сценарий очевидца — «открыл ссылку, поставил точку, закрыл» — при опоре на веб-пуши даёт нулевую доставляемость. Поэтому:

**Telegram-бот — основной транспорт уведомлений. Веб-пуши — бонус для тех, кто поставил PWA на экран.**

Побочная выгода: авторизация через Telegram отсекает часть абьюза бесплатно — у аккаунта есть возраст, username, бан работает.

### Механика фан-аута

При новом объявлении или отметке:

```sql
SELECT user_id FROM geo_subscriptions
WHERE active
  AND ST_DWithin(geog, :point, radius_m)
  AND (species_filter IS NULL OR :species = ANY(species_filter));
```

Дальше — в очередь, батчами.

### Защита от выгорания

Это самое хрупкое место. Люди отписываются от спама и не возвращаются.

- потолок уведомлений в сутки на пользователя
- тихие часы, по умолчанию 22:00–09:00, кроме отметок «животное у меня»
- дедупликация: несколько отметок по одному объявлению за короткий срок — одно сообщение
- дайджест вместо потока, если событий много

## 9. Приватность, безопасность, антиабьюз

### Приватность

- **EXIF.** GPS из фото очевидца — ценные данные для автопозиционирования отметки. Читаем на сервере, используем, но **обязательно вырезаем перед отдачей наружу**
- **Точка пропажи — это обычно подъезд владельца.** Публично показываем смещённую точку или круг радиусом 200–300 м. Точную — только в чате, по решению владельца
- Телефон не публикуется никогда. Только внутренний чат или телеграм
- Отметки анонимных пользователей не раскрывают IP и не хранят лишнего

### Абьюз

Типовые угрозы:

1. **Вымогательство** — «ваш пёс у меня, переведите N». Классика на всех таких сервисах. Митигация: нет публичного телефона, предупреждение в интерфейсе чата, кнопка жалобы
2. **Фейковые отметки** — из хулиганства или чтобы увести поиск. Митигация: вес отметки, репутация, скрытие по жалобам, ограничение частоты
3. **Спам и реклама** — фильтры, рейтлимиты, модерация
4. **Накрутка** — привязка к телеграм-аккаунту с историей

### Модерация

- Django-админка с очередью жалоб
- Автоскрытие при N жалобах до разбора
- Логи действий модераторов
- На старте модератор — сам автор проекта. Заложить это в оценку времени

## 10. Метрики

**Главная метрика — не регистрации.** Регистрации тут ничего не значат: человек пришёл один раз в кризисе и ушёл.

- Доля объявлений, получивших хотя бы одну отметку
- Медианное число отметок на объявление
- Время от публикации объявления до первой отметки
- Доля объявлений со статусом «найдено» (с оговоркой: люди забывают закрывать)
- Число активных гео-подписок по районам — это и есть плотность сети
- Доля отметок от повторных пользователей

Целевой ориентир для проверки жизнеспособности: **в пилотном районе больше половины объявлений получают отметку в первые сутки.** Если нет — плотность недостаточна, продукт не работает, сколько бы кода ни было написано.

## 11. Этапы

**Этап 0 — до кода.** Выбрать город и район. Найти 2–3 существующих локальных сообщества (чаты домов, зоогруппы), договориться о размещении. Без этого запускать бессмысленно.

**Этап 1 — ядро.** Модель данных, карта, объявление, отметка, бот с подпиской. Без чата, без трека — просто точки на карте.

**Этап 2 — трек.** Веса, зона поиска, временная шкала.

**Этап 3 — коммуникация.** Чат, жалобы, модераторская очередь, листовки с QR.

**Этап 4 — умное.** Автоподбор похожих, эмбеддинги, предсказание зоны.

## 12. Открытые вопросы

### 12.1 Монетизация — не решено

Сервис с UGC и модерацией стоит денег ежемесячно. Варианты:

| Вариант | Плюсы | Минусы |
|---|---|---|
| Полностью бесплатно + партнёрства с ветклиниками и приютами | Нет репутационного риска | Партнёрства долго собирать, дохода мало |
| Платное продвижение объявлений | Понятная модель, все так делают | Ровно то, за что конкурентов разносят в отзывах. Требует честной отчётности как отдельной подсистемы |
| Донаты | Честно | Непредсказуемо |
| Платные размещения для приютов и зоомагазинов | Не бьёт по владельцам в беде | Нужна аудитория, то есть не раньше этапа 3 |

Решение нужно до этапа 1, потому что платное продвижение — это отдельная подсистема, а не галочка в интерфейсе.

### 12.2 Прочее

- Город и район пилота
- Тайлы: своя сборка или Яндекс/2ГИС
- Нужна ли верификация по телефону в дополнение к телеграму
- Что делать с объявлениями, которые никто не закрыл — автоархив через N дней?
- Юрлицо и персональные данные: 152-ФЗ, политика обработки, хостинг в РФ
