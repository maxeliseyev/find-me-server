# Handoff (agent-based development)

Следующий человек или агент **не обязан иметь этот чат**. Всё, без чего нельзя
продолжить, живёт в git. Чат — черновик; источник правды — файлы ниже.

Протокол сжато в `AGENTS.md`. Здесь — шаблоны и «что куда».

---

## Что куда (один дом на факт)

| Факт | Куда | Не сюда |
|---|---|---|
| Где остановились, ветка, следующий шаг | `status.md` (перезаписывать) | чат, AGENTS, session note как единственная копия |
| Почему выбрали A, а не B | `sessions/YYYY-MM-DD-<topic>.md` | комментарий в модели, длинный PR |
| Решение, которое всплывёт снова | `decisions/<slug>.md` | session note без ADR |
| Продукт: роли, сценарии, модель данных, этапы | `spec-poisk-zhivotnyh.md` | код «на вырост» |
| Инварианты, которые нельзя «улучшить» | корневой `AGENTS.md` | README |
| Ветки, squash, когда `develop` | `git-workflow.md` | status.md |
| Неочевидное в одном месте кода | короткий комментарий рядом | эссе в docs |
| Открытые продуктовые вопросы (монетизация, город, тайлы) | раздел 12 спеки | status.md |

`status.md` — не лог. Лог = git + `sessions/`. Если он длиннее ~80 строк,
ты пишешь историю; вынеси её в session note и укороти статус.

---

## Старт сессии

Пока это не сделано — не писать фичу.

1. `git status -sb`, текущая ветка, `git log -5 --oneline`.
2. Открытые PR: `gh pr list`.
3. **`docs/status.md` целиком.**
4. Если статус ссылается на session note — прочитать её.
5. Если работаешь в зоне продукта — нужный раздел спеки, не всю спеку.

Если `status.md` расходится с git (указана ветка, которой нет; «сделано», а
файлов нет) — **сначала починить статус**, потом код. Сломанный курсор =
сломанная смена. `make status-check` сверяет поле Branch с текущей веткой.

---

## Конец сессии

Даже если работа не дописана. Уйти только в чат = потерять её для второго.

1. Код на **feature-ветке**, не на `main`. Закоммитить то, что запускается.
   Нерабочий промежуток — либо добить, либо откатить, либо явно описать
   в `Now` («падает миграция X, продолжать с файла Y»).
2. **Push ветки** (`git push -u origin HEAD`).
3. Переписать `status.md` по шаблону ниже. Branch / Now / Next / Resume обязательны.
4. Session note, если было решение, тупик или нетривиальный баг. **Why** обязателен.
5. ADR, если ограничение переживёт эту ветку.
6. Канон (спека, `AGENTS.md`) — в том же изменении, что и поведение.

Draft PR лучше, чем «продолжи из моего working tree».

---

## Шаблон status.md

Перезаписывать целиком. Дата — день правки.

```markdown
# Status

Updated: YYYY-MM-DD
Stage: N (<имя этапа по разделу 11 спеки>)
Step: <что именно из этапа>
Branch: feat/… | (none — работа в main working tree, так нельзя)
PR: url | none | draft
Blockers: none | …

## Done
- слито в main / есть на ветке (явно)

## Now
- что незавершено, какие файлы, что уже проверено

## Next
- один следующий шаг, не список на месяц

## Resume
1. git fetch && git checkout <branch>
2. make up && make migrate && make test
3. <конкретное действие>

## Open
- вопросы, которые блокируют Next. Пустой список = их нет.
```

## Шаблон session note

`docs/sessions/YYYY-MM-DD-<topic>.md`

```markdown
# YYYY-MM-DD — <topic>

## Context
Что спровоцировало работу.

## What
Конкретные файлы / поведение. Не «порефакторил».

## Why
Альтернативы и почему отвергнуты. Обязательная секция.

## Status
status.md обновлён: да. Ветка: …

## Next
Одна строка, та же, что Status.Next.

## Open
Известные дыры. Можно пусто.
```

Перед новым файлом — поиск по `sessions/` и `decisions/`. Дополнить
существующий, если это продолжение той же темы в тот же день.
