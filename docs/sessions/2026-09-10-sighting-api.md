# 2026-09-10 — API постановки отметки

## Context

Контракт репозитория закрыт (PR #1, #2), скелет стоит на PostGIS. Первый шаг
этапа 1 по `status.md` — главный сценарий продукта: очевидец ставит отметку.

## What

- `apps/sightings/serializers.py` — `SightingCreateSerializer` (вход lat/lon,
  время, источник; остальное необязательно) и `SightingSerializer` (публичное
  представление без автора).
- `apps/sightings/views.py` — `SightingCreateView`, `SightingDetailView`.
- `apps/sightings/throttling.py` — `anon_sighting` / `user_sighting`.
- `tests/test_sightings_api.py` (10 тестов) и два инварианта на уровне API:
  1 (анонимная отметка) и 12 (рейтлимит).

## Why

- **lat/lon вместо GeoJSON на входе.** Клиент этого эндпоинта — PWA, которая
  получает координаты из `navigator.geolocation`: два числа. GeoJSON пришлось
  бы собирать на клиенте ради формата, который здесь ничего не добавляет.
- **Привязка только к активному объявлению.** `PrimaryKeyRelatedField` с
  queryset по `status=active`: отметка на архивное объявление — это данные,
  которые никто не увидит. Неопознанная отметка при этом остаётся полноценной
  (инвариант 2), так что пользователь ничего не теряет.
- **Допуск 5 минут на будущее время.** Часы устройства уходят вперёд; жёсткое
  «строго не в будущем» отбрасывало бы валидные отметки. Три часа вперёд —
  уже ошибка ввода, её ловим.
- **Автор не раскрывается в ответе.** Раздел 9: отметки анонимных пользователей
  не должны выдавать лишнего. Тест проверяет, что username не встречается в
  теле ответа даже для авторизованного автора.
- **Фан-аут не подключён.** Задачи Celery ещё заглушки (`NotImplementedError`);
  вызов `.delay()` из вьюхи сейчас означал бы падение воркера при каждой
  отметке. Место вызова отмечено TODO и подключается в PR фан-аута.
- **Рейтлимит проверен мутацией**: снял `throttle_classes` — упал ровно
  инвариантный тест 12.
