# Исходник фото изолируется, публикуется только перекодированная копия

Status: accepted
Date: 2026-09-11

## Context

Фото могут содержать GPS EXIF, имя файла пользователя и вредоносные данные.
Клиентское сжатие и очистка уменьшают риск и трафик, но не доказывают, что
исходник безопасен: запрос можно сформировать без фронтенда.

## Decision

- Клиент по умолчанию пересохраняет фото без метаданных до загрузки; GPS при
  необходимости передаётся отдельными координатами после явного действия.
- Сервер повторно декодирует поддерживаемый JPEG, PNG или WebP, исправляет
  ориентацию, ограничивает размер и публикует только новый WebP без EXIF.
- Публичная копия получает случайное UUID-имя. SHA-256 перекодированной копии
  хранится как служебная метка, но не становится частью публичного URL.
- Исходник загружается только в приватный quarantine-префикс. Celery создаёт
  безопасную копию и удаляет исходник; публичный storage не получает оригинал.

## Alternatives

- **Доверять очистке на клиенте.** Её обходят старый клиент и прямой запрос.
- **Оставить исходник и удалить EXIF-теги.** Метаданные и опасные вложения
  надёжнее исключаются только повторным декодированием и кодированием.
- **Использовать SHA-256 как публичное имя.** Он позволяет проверить наличие
  известного файла по URL и связывать одинаковые публикации.

## Consequences

- Загрузка фото — два шага: приватная запись, затем асинхронная публикация.
- До завершения Celery-задачи API не отдаёт изображение наружу.
- Для object storage нужны отдельные правила доступа quarantine и published.
