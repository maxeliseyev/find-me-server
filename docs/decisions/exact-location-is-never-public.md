# Точная точка пропажи не публикуется, смещение детерминировано

Status: accepted
Date: 2026-09-09

## Context

Точка последнего наблюдения в объявлении о пропаже — это, как правило, подъезд
владельца. Карта публична и открыта без авторизации. Отдавать координаты как
есть — значит публиковать домашний адрес человека, который сейчас в кризисе,
рядом с текстом «меня нет дома, я ищу собаку».

## Decision

- В публичную выдачу идёт `LostReport.public_geog` — точка, смещённая на
  случайный вектор внутри круга `PUBLIC_LOCATION_BLUR_M` (по умолчанию 250 м).
- Смещение **детерминировано** по id объявления (`seed=f"report:{pk}"`).
- Точная точка отдаётся только владельцу и только по его явному решению
  (`location_precision = exact`) или в чате.
- Отметки очевидцев смещению не подлежат: их ценность в точности, и они не
  указывают на жильё владельца.

## Alternatives

- **Отдавать точную точку.** Публикация домашнего адреса. Не обсуждается.
- **Случайное смещение на каждый запрос.** Наивный вариант, который выглядит
  безопаснее и таковым не является: несколько запросов усредняются, и центр
  распределения — исходная точка. Ошибка тем хуже, чем незаметнее.
- **Отдавать только круг без центра.** Клиенту всё равно нужна точка для
  кластеризации и сортировки; круг рисуется поверх смещённой точки.
- **Обнулять младшие разряды координат (rounding to grid).** Сетка выдаёт
  привязку к ячейке; на разреженном районе ячейка = дом.

## Consequences

- Публичный сериализатор объявления обязан отдавать `public_geog`; тест на то,
  что точная координата не попала в ответ, — обязательный.
- Смещение стабильно между запросами: карта не «дрожит» при перезагрузке.
- Радиус — настройка, а не литерал: пилотный район может потребовать другого.
