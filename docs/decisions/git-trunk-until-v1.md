# Git: trunk на main до первого запуска

Status: accepted
Date: 2026-09-09

## Context

Репозиторий пустой, разработка ведётся владельцем и агентами. Нужен
обязательный PR-поток (агент не должен молча писать в интеграционную ветку)
и ответ на вопрос, заводить ли `develop` сейчас.

## Decision

До первого запуска на пилотном районе:

- долгоживущая ветка одна — `main`;
- вся работа через PR в `main`, включая владельца репо и агентов;
- squash-merge;
- ветки `feat/` `fix/` `chore/` `docs/` `test/` короткоживущие;
- `develop` не создавать;
- правило механическое, а не текстовое: GitHub ruleset на `main` (запись
  только через PR, без force-push и удаления) плюс локальный pre-commit хук.

После `v1.0.0` — `develop` как интеграция следующей линии, `main` как
развёрнутое, хотфиксы в `main`. Подробности: `docs/git-workflow.md`.

## Alternatives

- **Git Flow сейчас.** Пользователей нет, `main` пустеет, каждый PR целит не
  туда, агенты путают целевую ветку. Церемония релиза без релиза.
- **Прямой пуш в `main`.** Именно то, что ломается при работе с агентами:
  нет границы «готово к интеграции», нет места для ревью, нет точки, где
  человек видит диff до того, как он стал историей.
- **Правило только в AGENTS.md, без ruleset.** Текстовое правило нарушается
  ровно в тот момент, когда его цена выше нуля («тут же мелкая правка»).
  Механический запрет стоит один раз и работает всегда.
- **Trunk + обязательный PR + ruleset** — выбран.

## Consequences

Защищать нужно только `main`. Merge своих PR без ревью разрешён (пометка
`self-merge:` в описании) — иначе один разработчик заблокирует сам себя.
Когда появится `develop`, `AGENTS.md`, `git-workflow.md` и ruleset
обновляются одним изменением, не раньше.
